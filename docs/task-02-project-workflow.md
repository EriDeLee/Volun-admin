# 项目权限与持久化工作流设计及施工说明

本文件是本次权限调整的实施基线；项目书中未施工的地图、WPS迁移、后台任务及批量预检仍属于后续建设内容，不代表已上线能力。

## 职责与流程

活动管理员创建本人项目，填写基础信息、场次和岗位，提交立项。数据管理员共享所有已提交项目及审核池，批准后承接招募、成员维护、问卷及二维码、意向、时长登记/粘贴导入/补录/更正、附件1、外部录入结果和最终审核。活动管理员保留成员查看、现场签到签退及已生成附件下载能力。数据管理员不能创建项目，也不能查看其他人的未提交草稿。超管保留全局权限，正式用户仅访问本人记录和公开问卷。

审批状态独立于十二种业务状态：草稿 draft → 待审 pending → 批准 approved / 退回 returned。退回必须给出理由，可修订重提。初次批准进入“筹备”。批准后的基础信息与场次变更由两类管理员提出，数据管理员审批，允许审批本人变更；审批前原版本继续生效，不允许移除已有成员使用的场次岗位。

批准后业务状态按“筹备→招募→进行→结项→意向→统计→数据→录入→审核→通过”推进，审核可以驳回或退回数据处理阶段；通过/驳回可有理由重开到统计或数据。所有转换必须显式触发并说明原因。申请录入者需有小时记录；进入审核必须登记外部录入结果。审核及终态锁定数据写入，通过发布认定结果，重开撤回发布。

## 现场出勤与本人身份

签到和签退分开配置，支持手动开关和服务器时间窗口。活动管理员只能在开放窗口记录；数据管理员可以有理由更正。扫码必须持有当前场次窗口令牌，并验证可信账号与成员的已有绑定，或本人专属访问凭证。相同动作重复扫码返回原记录，不重复写入。出勤事实不自动生成小时数。

招募问卷允许匿名登记，使用随机幂等键防重复提交，返回本人凭证；数据库仅保存摘要，浏览器交换为 HttpOnly、SameSite Cookie。分享凭证通过 URL fragment 传递，页面交换后清除。凭证有有效期，可撤销/重发；撤销后不得用原报名幂等键恢复访问。自行填写的学号只用于查重，不证明本人身份；账号绑定由数据管理员确认，或本人持有效凭证且可信账号编号匹配后完成。SSO返回继续本人页面，首次账号设置密码后保留返回位置。

## 数据与一致性

迁移 v4 增加 projects.approval、workflows、workflow_events、material_versions、participant_grants。旧立项项目初始化为草稿，其他旧项目初始化为批准，旧数据不伪造审批历史。

当前业务明细以每项目 JSON 聚合存放在 workflows.state，包含场次、审批申请、成员、问卷、出勤窗口、出勤事实、小时、材料配置和审核快照。并非逐项规范化关系表。每次写入在同一数据库事务内比较聚合版本、更新项目摘要并写入事件快照；冲突返回 100003，前端需刷新后重试，不静默覆盖。管理端写入提交 X-Workflow-Version；公开提交也在提交时执行数据库版本比较。事件内部身份、完整快照及账号绑定不暴露到 API。

小时使用可空整数：null 表示未登记，0 表示明确零小时。批量保存原子提交，不能混入小数或负数；补录、更正需要理由。审核中及终态禁止直接修改，数据管理员先有理由退回/重开。个人接口只返回本人事实和已发布时长，活动管理员不读取内部时长草稿。

附件1使用 internal/activity/templates/attachment1.docx 原学校模板，按既有导出映射替换表格字段、克隆岗位行，保留标题、表格与复选内容，正文仿宋。每次生成的私有 DOCX 及模板摘要、文件摘要、版本持久保存，下载再次检查项目范围。CSV导出防公式注入并记审计事件。

## 页面与接口

项目详情整合基础信息/审批、成员、现场出勤、问卷、小时、附件及审核历史标签，按服务端 capabilities 展示操作。活动管理员侧边栏移除小时和材料管理入口；数据管理员不能使用创建按钮。公开 /signup?project=... 提供报名、本人资料、意向及扫码确认。

工作台、项目页、成员管理及个人信息页共用 Sidebar 组件：超管可见工作台、项目台账、时长管理、项目材料、成员管理、公开问卷、个人信息；数据管理员无平台成员管理入口；活动管理员仅见工作台、项目台账及个人空间；正式用户仅见公开问卷和个人信息。成员管理对应平台账号及用户组，项目志愿者名单在项目详情维护。时长/材料入口先选择项目，再进入对应标签，保留当前菜单高亮。公开填写页面独立展示，不显示后台导航。

管理接口前缀 /api/v1/activity/projects/:id：GET workflow/history，PUT basics/members/forms/windows/hours/material，POST submit/changes/applications/:applicationID/decision/members/access/transition/material/generate，GET members/export/forms/qr/sessions/:sessionID/qr/:action/material/:fileID，POST sessions/:sessionID/attendance。

公开接口前缀 /api/v1/public/projects/:id：GET forms/:formID，POST forms/:formID/responses，POST access，GET/PUT me，POST me/bind，GET/POST sessions/:sessionID/scan。公开接口限流、禁止缓存；写请求要求 X-Requested-With: XMLHttpRequest。

二维码使用请求Host和反向代理的HTTPS标识生成，部署必须保留外部Host，并正确设置转发协议，确保链接指向前端 /signup。真实学校SSO和不同办公软件的附件版式兼容性需要部署环境验收。

## 验收重点

- 跨活动管理员隔离、数据管理员草稿隔离、正式用户禁止后台访问。
- 活动管理员不得维护招募、问卷、小时、材料或业务状态；数据管理员审批和数据操作必须通过后端校验。
- 版本过期不能覆盖数据；未批准变更不影响当前版本。
- 报名身份、凭证撤销、窗口关闭、跨场次签到、重复扫码均按上述规则执行。
- 出勤不产生小时；负数、小数、缺失小时不能混作零；审核锁定及重开撤回发布。
- 附件原模板字段映射、私有下载、不可变版本及审计事件可追溯。
