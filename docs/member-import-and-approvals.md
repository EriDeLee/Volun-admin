# 平台成员导入与项目审批

本次“成员”按侧边栏的成员管理，即平台登录账号实现；项目内志愿者名单仍在项目详情维护。

## 单独添加与密码重置

超管可以在成员管理点击「添加成员」，填写姓名、编号、登录账号、初始密码和用户组。编号作为文本保存。该操作使用与CSV导入一致的校验、重复账号检查和初始化逻辑，创建后必须首次设密。

列表内「重置密码」允许超管为其他成员设置临时密码，同时撤销该成员全部会话。下次使用临时密码或学校SSO登录后，必须完成设密才能访问业务功能。密码仅保存bcrypt摘要，接口不回显密码。超管应单独告知成员临时密码。

重置不改变账号启停状态和用户组；停用账号仍不能登录。当前登录超管自身及用户名对应多个身份的账号不能在此重置，避免误操作。

新增接口：`POST /api/v1/admin/users`，请求字段为 `username`、`name`、`id`、`password`、`groups`，返回结构同导入，逐行校验错误不会写入账号。

重置接口：`POST /api/v1/admin/users/:username/reset-password`，请求 `{ "password": "临时密码" }`，成功返回成员公开信息。两者仅超管可调用，并要求 `X-Requested-With: XMLHttpRequest`。

## 成员导入

超管进入「成员管理 → 批量导入」，下载CSV模板，填写UTF-8文件，上传或粘贴内容后预检，确认无误再导入。每批最多100人，文件选择上限200KB，接口JSON体上限256KiB。

表头固定为 `账号,姓名,学号,初始密码,用户组`。学号和账号应以文本填写，保留前导零。初始密码12至72字节，用户组使用四种固定代码，多个用 `|` 分隔，留空为 `formal_user`。密码不在预检结果中回显，不存储到浏览器本地存储，服务端仅保存bcrypt摘要。

预检不写入数据。提交时重新校验，文件内重复、已有账号或任何无效行都会阻止整批导入。新增账号启用，首次凭初始密码登录后必须设置新密码才能访问业务功能。初始密码由超管通过适当渠道单独告知成员。

接口：`POST /api/v1/admin/users/import`，请求 `{ "csv": "...", "commit": false }` 预检；`commit: true` 提交。响应包含 `valid`、`imported`、`rows`，逐行返回行号和错误说明。

## 项目审批

超管和数据管理员在侧边栏「项目审批」集中查看待审立项及已批准项目的待审基础信息变更，支持按项目名称、编号、申请人搜索和分页。点击「查看并审批」打开项目详情核对申请内容，填写至少两字的审核意见后通过或退回。

立项退回后允许活动管理员修订重提；立项通过进入筹备。变更待审期间原版本继续生效，通过后才应用申请内容。申请理由、审核意见、审核人及审核时间分别保留，新审批不会覆盖申请理由；历史旧记录继续兼容显示。

列表接口：`GET /api/v1/activity/approvals?q=&page=1&page_size=20`。审批沿用项目工作流版本检查及审计事件；列表不允许直接批量通过。

验证使用临时SQLite数据库和前端模拟请求；生产PostgreSQL并发导入及学校SSO尚未现场联调。本地导入账号不自动绑定学校SSO身份。
