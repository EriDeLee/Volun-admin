# 志愿服务平台前端

在本目录运行：

```powershell
npm install
npm run dev
```

前端地址为 `http://localhost:5173`，同源 `/api` 由 Vite 代理到 `127.0.0.1:8080`。需在仓库根目录另行启动 `go run ./cmd/api`。SSO 的域名与回调配置遵循根目录 README，避免混用 localhost 与 127.0.0.1。

- `/login`：账号密码登录、密码显隐、学校统一认证、失败提示和重试。
- `/set-password`：新 SSO 身份首次登录后的必经页面，设置平台密码。
- `/profile`：受保护的个人信息页，展示真实姓名、账号、学号 / 人员编号、用户组和会话状态；不显示平台内部用户标识。支持刷新和退出。
- `/`：先验证服务器会话，再进入登录或个人信息页面。
- `/preview/`：此前的独立设计预览，使用演示数据，不连接认证接口。

页面沿用预览的白蓝配色、双栏登录布局与侧栏个人空间；手机端收起侧栏并使用单列布局。没有公开注册、找回密码或资料修改接口，因此不展示这些操作。

启动时请求 `GET /api/v1/auth/me` 恢复身份；401 返回登录，网络故障和服务故障提供重试。账号密码通过 `POST /auth/login` 提交，学校认证通过后端 `/auth/sso/start` 整页导航。登录失败保留账号并清空密码；身份及密码不写入 localStorage 或 sessionStorage。退出仅在服务器请求成功后清空身份，网络失败保留页面供重试。

当前 `/auth/me` 的 `auth_method` 为 `session`，因此刷新后显示「已通过会话验证」，不推断最初是 SSO 还是密码登录。全新的 SSO 用户会看到 `password_setup_required` 状态，并且后端拒绝其访问受保护功能和账号密码登录，直至设置 12 至 72 字节的 bcrypt 密码。若学校未提供 username，设置页会展示平台生成的随机登录账号。用户组只展示服务器返回的实际成员关系，不因页面展示授予权限。

## 检查

```powershell
npm test
npm run format:check
npm run build
```

测试在 jsdom 中模拟接口，覆盖身份恢复、前导零编号、登录失败与成功重试、会话恢复网络故障、退出失败重试、会话失效、SSO 错误提示与入口、重复提交。尚未进行学校真实 SSO 联调与浏览器截图验收。

正式部署需要将 `/login`、`/profile` 等页面地址回退到 `index.html`，并保持认证接口和 SSO 回调交给后端。
